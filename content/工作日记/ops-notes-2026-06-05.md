# 运维与开发问题记录 (2026-06-05)

## 一、物理机 + KVM 虚拟机资源检查

### 环境
- 物理机：128G 内存，32 核 CPU（Xeon, 1 socket × 8 cores × 2 threads），3T /home 磁盘
- 虚拟化工具：virt-manager
- 4 台虚机：96、94、93、generic，全部 running

### 资源分配情况

| 虚机 | vCPU | 内存 |
|------|------|------|
| 96 | 8 | 31.25 GiB |
| 94 | 8 | 31.25 GiB |
| 93 | 8 | 31.25 GiB |
| generic | 8 | ~30 GiB |
| **合计** | **32** | **~123.75 GiB** |

### 宿主机剩余资源

| 资源 | 总量 | 已分配 | 剩余 |
|------|------|--------|------|
| CPU | 32 核 | 32 vCPU | 0 |
| 内存 | ~125.6 GiB | ~123.75 GiB | ~1.85 GiB |
| 磁盘 /home | 3 TiB | 2.3 TiB | ~721 GiB |

### 结论
- **CPU 和内存都在满负荷边缘**，宿主机可用内存仅 ~1.85G，Swap 4G 已打满
- 热减配（不停机减 CPU/内存）在 virt-manager 默认配置下基本不可行：CPU 热拔需要 maxvcpus > current vcpus 预设，内存热拔需要 virtio-mem 等特定配置，默认建虚机不会开这些
- 唯一可行方案：找维护窗口，关机调小配置再启动

### 有用命令
```bash
# 虚机列表
virsh list --all

# 宿主机总资源
virsh nodeinfo

# 每台虚机详情
virsh dominfo <虚机名>

# 批量查看内存分配
for vm in 96 94 93 generic; do
  echo "=== $vm ==="
  virsh dominfo $vm | grep -E "CPU|内存"
done
```

## 二、Python 项目依赖修复

### 项目：proxy_brower（爬虫/浏览器自动化）

### 问题 1：DrissionPage 版本不存在

```
ERROR: No matching distribution found for DrissionPage==4.1.1.2
```

**原因**：`4.1.1.2` 在 PyPI 上不存在（4.1.1.x 系列只有 .0, .1, .3, .4）

**修复**：`requirements.txt` 中 `DrissionPage==4.1.1.2` → `4.1.1.3`

### 问题 2：async-timeout 版本冲突（多次）

- **第一次冲突**：`async-timeout==3.0.1` 不满足 `aiohttp 3.11.0` 要求的 `>=4.0`
  - **修复**：`3.0.1` → `4.0.1`
- **第二次冲突**：`async-timeout==4.0.1` 不满足 `redis 5.2.0` 要求的 `>=4.0.3`
  - **修复**：`4.0.1` → `4.0.3`

### 问题 3：typing-extensions 版本警告

`cryptography 46.0.4` 要求 `typing-extensions>=4.13.2`，但 requirements.txt 锁成了 `4.12.2`

**修复**：改为 `typing_extensions>=4.13.2`

### 最终修改汇总

| 包名 | 原版本 | 新版本 |
|------|--------|--------|
| DrissionPage | 4.1.1.2 | 4.1.1.3 |
| async-timeout | 3.0.1 | 4.0.3 |
| typing_extensions | 4.12.2 | >=4.13.2 |

## 三、CentOS 7 安装 Python 3.10 via pyenv

### 环境
- CentOS Linux 7 (Core)，内核 3.10.0-1160
- 系统自带 Python 3.6.8（已停止维护）
- 项目代码使用了 `match` 语法，需要 Python >= 3.10

### 关键限制
- CentOS 7 官方镜像站已下线，yum 源需切到 vault.centos.org
- 系统 GCC 4.8.5 最高只能编译 Python 3.10（3.11+ 需要 GCC 7.5+）
- 系统 OpenSSL 1.0.2k 太老，编译时必须指定 openssl11

### 安装步骤

#### 1. 修复 yum 源
```bash
sed -i 's/mirrorlist/#mirrorlist/g' /etc/yum.repos.d/CentOS-*
sed -i 's|#baseurl=http://mirror.centos.org|baseurl=http://vault.centos.org|g' /etc/yum.repos.d/CentOS-*
sed -i 's|http://mirror.centos.org|http://vault.centos.org|g' /etc/yum.repos.d/CentOS-*
yum clean all && yum makecache
```

#### 2. 清理 SCLo 源（如果之前装过 centos-release-scl）
```bash
yum remove -y centos-release-scl
rm -f /etc/yum.repos.d/CentOS-SCLo-scl*
grep -r "sclo-rh" /etc/yum.repos.d/   # 确认清理干净
```

#### 3. 装编译依赖
```bash
yum install -y gcc make openssl11-devel bzip2-devel libffi-devel zlib-devel readline-devel sqlite-devel
```

#### 4. 装 pyenv
```bash
git clone https://github.com/pyenv/pyenv.git ~/.pyenv
echo 'export PYENV_ROOT="$HOME/.pyenv"' >> ~/.bashrc
echo 'export PATH="$PYENV_ROOT/bin:$PATH"' >> ~/.bashrc
echo 'eval "$(pyenv init -)"' >> ~/.bashrc
exec $SHELL
```

#### 5. 从华为云镜像下载 Python 源码（pyenv 直连 python.org 可能很慢）
```bash
cd /tmp
curl -O https://mirrors.huaweicloud.com/python/3.10.14/Python-3.10.14.tar.xz
mkdir -p ~/.pyenv/cache
cp Python-3.10.14.tar.xz ~/.pyenv/cache/
```

#### 6. 编译安装 Python 3.10.14
```bash
CFLAGS="-I/usr/include/openssl11" \
LDFLAGS="-L/usr/lib64/openssl11 -lssl -lcrypto" \
pyenv install 3.10.14
```

#### 7. 切换项目 Python 版本
```bash
cd /path/to/proxy_brower
pyenv local 3.10.14
python3 --version   # Python 3.10.14
```

#### 8. 安装项目依赖
```bash
pip3 install -r requirements.txt
```

## 四、踩坑备忘

1. **Python 版本与语法**：`match` 语句是 Python 3.10 引入的（PEP 634），3.9 会报 `SyntaxError: invalid syntax`
2. **CentOS 7 yum 源已下线**：所有 mirrorlist 都挂了，必须切到 `vault.centos.org`
3. **SCLo 源卸载不干净**：`centos-release-scl` 卸载后 repo 文件可能残留，需要手动 `rm`
4. **pyenv.run 连不上**：直接 `git clone` GitHub 仓库，功能一样
5. **python.org 下载慢**：用华为云镜像预下载到 `~/.pyenv/cache/`，pyenv 会跳过下载直接编译
6. **OpenSSL 是关键**：CentOS 7 系统 OpenSSL 太老，必须装 `openssl11-devel` 并在编译时指定路径，否则 pip 装包时 SSL 报错
7. **GCC 版本限制**：系统 GCC 4.8.5 最高支持 Python 3.10，要装 3.11+ 需先装 devtoolset 拿新版 GCC

## 五、Python 进程管理（run.py）

### 启动
```bash
nohup python3 run.py &
```
输出重定向到 `nohup.out`，不会因终端关闭而退出。

### 查看
```bash
# 只看 run.py 进程
ps aux | grep run.py | grep -v grep

# 看所有 Python3 进程（含宝塔面板等）
ps aux | grep python3 | grep -v grep
```

### 杀死
```bash
# 只杀 run.py 进程（推荐，不误伤其他 Python 进程）
pkill -9 -f "run.py"

# 确认杀干净
ps aux | grep run.py | grep -v grep
```

### 注意
`pkill -9 python3` 会连宝塔面板的 supervisord 一起杀掉，不要用。用 `-f "run.py"` 按命令行参数精确匹配。
